# Sprint 8 – User manual and Help Center

## Goal

A detailed `docs/user-manual.md` and a Help Center inside the GUI, both with screenshots.

## Decisions

| Topic | Decision |
|-------|----------|
| One source | The Help Center renders `docs/user-manual.md` itself (plus `docs/SCRIPTING.md`), embedded into the binary. There is no second copy of the text to drift |
| Screenshots | Generated by `scripts/screenshots.js` (Playwright against a seeded throw-away workspace), stored once in `ui/help/img/` – referenced by the manual on GitHub and served to the Help Center. Regenerate with `cargo build && node scripts/screenshots.js` after UI changes |
| Rendering | A small Markdown renderer (`ui/js/md.js`) that builds DOM nodes and never uses `innerHTML`; it supports exactly what the manual uses |
| Structure | One Help topic per `##` chapter, with search across all text, previous / next, and in-text links between chapters |
| Reaching it | **F1**, a **?** button in the top bar, a link on the welcome screen, and a **?** beside the title of every tool page that opens the matching chapter |
| Audience | Written for someone using the application, not for someone reading its source: what each control does, in the order one meets them, then the command line |

## Scope

1. Manual: getting started, main window, requests, responses, collections, variables,
   authorization, scripts, runner, mock servers, WebSocket, benchmark, LLM profile, vault and
   credentials, cookies, history, import / export / snippets / docs, settings, command line,
   shortcuts, files on disk, troubleshooting.
2. 24 screenshots.
3. Help Center view, Markdown renderer, backend routes, contextual help buttons.
4. Tests: manual ↔ screenshots ↔ anchors consistency; Help Center behaviour; renderer safety.
