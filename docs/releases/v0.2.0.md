# rsPostman 0.2.0

Released 2026-11-11.

This release makes rsPostman safer to use with real credentials, turns the
benchmark into a proper load-testing tool, and adds documentation you can read
without leaving the app.

## Highlights

### Local vault

Secrets can now live in an encrypted vault instead of in plain environment
files. Values are encrypted at rest with a key derived from your passphrase and
referenced from any request field as `{{vault:name}}`.

```bash
rspostman vault init
```

```bash
rspostman vault set api-token
```

Vault values are never written to history, reports or logs. The GUI has a
Vault screen for the same operations.

There is no passphrase recovery: if the passphrase is lost, the vault contents
are lost with it.

### Safer credential handling

- Password and token fields are masked in the GUI and prompted for without
  echo in the CLI.
- History, run reports and verbose output show `<redacted>` in place
  of credentials. Set `history_store_secrets` to keep them if you need to.
- Workspace files are private to your user (`0600` files, `0700` directories).

### Benchmark

- Run for a fixed duration or a number of iterations, with concurrency, a
  target request rate and a warm-up period.
- Results include time to first byte, percentiles up to p99.9, a latency
  histogram and a timeline.
- Thresholds turn a run into a pass/fail check, usable in scripts.
- Compare a run against a saved baseline to spot regressions.
- Export results as CSV or a self-contained HTML report.
- The GUI charts a run live and can cancel it.

The benchmark is a closed-loop client running on one machine; treat its
numbers as a comparison between runs rather than as an absolute capacity
figure.

### LLM provider profiler

A profiler for chat-completion style endpoints, in the CLI and the GUI, that
reports latency and streaming behaviour.

### User manual and Help Center

`docs/user-manual.md` covers every screen and command with screenshots. The
same manual opens inside the app from the Help button or `F1`, with search and
a help button on each tool screen that jumps to the matching chapter.

## Upgrading from 0.1.0

- Existing workspaces are read as they are; no migration is needed.
- History entries recorded from now on have credentials redacted. Earlier
  entries are left unchanged.
- Scripts or tools that call the GUI server's API directly must send
  `X-Requested-With: rspostman` on non-GET requests.
- If you used `-q` with `rspostman benchmark`, use `--quiet`.

## Known limitations

- The vault has no passphrase recovery and no auto-lock.
- The desktop shell has only been tested on Linux.
- The repository has no continuous integration; run `scripts/test-all.sh`
  before relying on a build.
